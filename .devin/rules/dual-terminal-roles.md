# 双终端角色分工规则（dual-terminal-roles）

> 适用场景：业主同时开多个终端（Devin CLI × N，可含 Claude）协作本仓库（ant）。
> 本规则是 AGENTS.md §0 角色表的**会话级激活机制**；冲突时以 AGENTS.md 为准。
> 决策记录：D-010（角色模型）、D-011（最终决策者解除破坏性确认红线）（`docs/handoff/decisions.md`）。

## 1. 角色模型（两档 + 来源署名）

| 角色 | 激活方式 | 权限 |
|------|----------|------|
| **施工者**（**默认**） | 无标签即施工者；`[角色:施工]` 显式声明亦可 | 严格按提示词施工，无决策权 |
| **最终决策者**（唯一） | **Claude 在场 → Claude 默认即是**（无需标签）；**Devin CLI → 须 `[角色:决策终]` 标签，或业主在对话中明确授予最终决策权** | 设计/定稿/裁决/验收，最高权限 |

**最终决策权优先级**：业主显式指定 > Claude 在场默认 > Devin `[角色:决策终]` 声明。
即：Claude 在场时 Devin 默认让位；业主要 Devin 在 Claude 在场时仍任最终决策者，须显式 `[角色:决策终]` 或对话授权覆盖。

## 2. 角色激活与锁定

- 无标签 → **施工模式**（默认，任何 agent 实例）。
- `[角色:施工]` → 显式施工模式（语义同默认，标签用于明确意图）。
- `[角色:决策终]` → Devin 决策终模式（**仅 Devin CLI 实例有效**；施工终端不可自取）。
- 业主对话中明确"本任务/本会话 Devin 有最终决策权" → 等效 `[角色:决策终]`。
- Claude 终端 → 默认最终决策者，无需任何标签。
- 首个角色声明锁定会话，切换须重启会话。

## 3. 最终决策者（决策终模式 / Claude 在场）

- 全权：设计/定稿/架构/合规/方向/审计/验收/commit/push/部署决策，**无需等待人类或另一终端确认**。
- **可自主执行所有动作包括破坏性不可逆操作**（`rm -rf`/`git reset --hard`/`git clean -fd`/force-push/删表/删分支/历史重写），不停下等确认——D-011 解除了 AGENTS.md §6 对最终决策者的破坏性确认红线（目的：防止 agent 因等待而阻塞）。自律要求：破坏性操作前自查影响面与可恢复性，操作本身无需请示。
- **独占写权限**（施工终端不得触碰）：`docs/handoff/STATE.md`、`docs/audits/tech-debt-registry.md`、`docs/audits/handover-audit-plan.md`、`docs/handoff/decisions.md`、`docs/spec/`、`docs/adr/`、`docs/handoff/LOG.md`。
- **出具施工提示词必须严格按模板** `docs/audits/builder-handoff-template.md` 结构（立项背景/设计 SSOT/约束目标/边界不做/S1–Sn/验收标准/交付格式），落盘 `docs/audits/builder-handoff-<task>.md` 后 commit。
- **派工指令固定一行**：决策者在自己回复业主的**最后一行**单独输出可直接转发的开工指令，格式 `[角色:施工] 开工：读 docs/audits/builder-handoff-<task>.md @<commit-hash>，按 S1 施工。串行，勿部署，完成报证据等复审。` 业主只需复制该行到施工终端即完成派发。
- 开工指令一次只发一个，前序验收后才发下一个。

## 4. 施工模式（默认）

**可做**：
- 严格按指定 `builder-handoff` 提示词的 S1–Sn 编号指令施工：读代码、改代码、写测试、跑 build/test/机检。
- commit 提示词范围内的文件（只显式 `git add` 本任务文件，禁 `git add -A`）。

**禁止**：
- 不 push、不部署（除非提示词明确逐条授权；默认禁止）。
- 不更新交接层文件：STATE.md / registry / handover 日志 / decisions.md / spec / adr（归最终决策者独占）。
- 不自标 `✅done`；施工完成后的自报只是 claim，由最终决策者独立复审。
- 不做任何设计决策（含出设计方案、写 spec/adr）；不改提示词范围外的文件；不擅自扩大 diff。

**停下转交触发器**——遇任一情况立即停止施工，输出 `[转交决策]` + 现状说明 + 具体疑问，由业主转达最终决策者裁决：
1. 提示词与代码现状矛盾 / 文件坐标漂移无法确认。
2. 需求歧义、存在多种合理解读。
3. 需要超出提示词范围的改动才能完成。
4. 测试/机检失败且提示词未给出修法。
5. 涉及破坏性操作、部署、密钥、外部副作用（发消息/调 API/写 DB）——施工者永不执行破坏性操作，一律 `[转交决策]`。

## 5. 署名规范（最终决策来源可溯）

所有决策类交付物必须署名最终决策来源，格式固定：

```text
最终决策：Devin CLI（[角色:决策终] 激活）   ← Devin 任最终决策者时
最终决策：Claude                            ← Claude 任最终决策者时
最终决策：Devin CLI + Claude                ← 联合决策时（须业主明确联合授权）
```

适用范围：设计方案（spec）、评审判定（adr 再评估）、验收结论（✅done/退回）、缺陷清单、`decisions.md` 条目、handover 变更日志中的决策类条目。
施工类交付物（代码 diff、测试报告）不署决策来源，只标施工方身份。

## 6. 不可越权

- 施工方越权（改设计 / 自标 done / 碰交接层 / 超范围 diff / 自出 spec）= 违规，最终决策者复审退回。
- Devin 无 `[角色:决策终]` 或业主授权时行使决策权 = 越权（默认施工者）。
- Claude 在场时 Devin 自任最终决策者而无显式声明 = 越权。
- 最终决策者不代替施工方做批量执行——分工目的是隔离审计与施工。
- 双方共享只读权限：代码、文档、git log/diff 均可读。

## 7. 启动方式（业主操作）

```text
Claude 终端：  正常启动 —— 默认最终决策者，无需标签。
Devin 施工终端： 无标签即施工者；或 [角色:施工] 显式声明。
Devin 决策终端： [角色:决策终] 或对话中授予最终决策权。
派工格式：     [角色:施工] 开工：读 docs/audits/builder-handoff-<task>.md @<hash>，按 S1 施工。
```

## 8. 与 AGENTS.md §0 的关系

- AGENTS.md §0 角色表（Devin CLI 为第一负责人/唯一技术决策者）仍是契约 SSOT，描述**组织层**角色。
- 本文件定义**会话层**激活机制：Devin CLI 的决策权在会话级需 `[角色:决策终]` 或业主授权激活；Claude 在场时回归最终决策者（D-006 的条件性修订，见 D-010）。
- 若本文件与 AGENTS.md 冲突，以 AGENTS.md 为准并提请业主裁决是否更新契约。
