# 完整解决方案：完全替代 MetaTrader 跑 EA

> **日期**：2026-06-22
> **目标**：让任意 MT4/MT5 EA，经翻译后，在**回测与实盘**中表现与 MetaTrader **行为一致**，安全、可多租户运行，最终**完全替代** MT 跑 EA。
> **约束**：可接受重构；不以最快落地、不以最省成本为目标；**只求最优解**。
> **基线**：见 `docs/audit/2026-06-22-策略EA执行系统-现状地图.md`。

---

## 0. 核心判断：要建模的是「券商 + 事件模型」，不是「语言」

当前方案失败的根因，是试图把 EA 逻辑塞进一个"每根 bar 返回一个 signal 字典"的薄模型。EA 真正依赖的只有两样东西：

1. **事件模型**：`OnInit / OnTick / OnTimer / OnTrade / OnDeinit`（注意是 **OnTick 逐 tick**，不是逐 bar）。
2. **交易服务器语义**：订单 / 持仓 / 成交（order/position/deal）、保证金、成交规则、requote、stops/freeze level、netting vs hedging、magic number、部分平仓、挂单。

**只要把这两样建模得足够忠实，EA 翻译就退化为近乎机械的映射，行为自然与 MT 对齐。** 这是整个方案的基石——语言（Python/Go/Rust）反而是次要选择。

## 1. 北极星架构（目标态）

```
┌─────────────────────────────────────────────────────────────────────┐
│                         翻译层 (MQL → SDK)                            │
│   确定性 Transpiler (MQL4/5 AST) ──► SDK 代码骨架                      │
│                       │  flag 无法机械翻译处                           │
│                       ▼                                               │
│              LLM 补全 (面向精确 SDK 规格 + few-shot)                   │
│                       │                                               │

└───────────────────────┬───────────────────────────────────────────────┘
                        │ 产出：统一 Strategy SDK 代码
                        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   统一策略运行时 USR (同一份代码)                      │
│   Strategy SDK: on_init/on_tick/on_bar/on_timer/on_trade/on_deinit     │

                        ▼

└──────────────┬───────────────┘     └───────────────┬────────────────┘
              │            两条路径共用同一份策略代码  │

              ┌──────────────────────────────────────────┐
              │   执行 & 风控网关 (Go，金钱安全边界)        │
              │   逐单：手数/持仓/敞口/日亏熔断/白名单/限频  │
              │   全局 kill-switch + 保证金预检            │
```

### 1.1 统一策略运行时 USR（Strategy SDK）

一套**忠实镜像 MQL 语义**的 SDK，让翻译近乎 1:1：

- **生命周期**：`on_init()`、`on_tick()`、`on_bar()`、`on_timer()`（配 `set_timer`）、`on_trade()`、`on_deinit()`。
- **上下文对象**：
  - `Symbol`：`digits, point, tick_value, tick_size, contract_size, volume_min/max/step, stops_level, freeze_level, swap_long/short, margin_rate`
  - `Account`：`balance, equity, margin, free_margin, margin_level, leverage, currency`
  - `Series`：`close[], open[], high[], low[], volume[], time[]`，**采用 MQL 的逆序索引语义**（`close[0]` 为当前 bar）
  - `Indicators`：`ma/rsi/bands/macd/atr/stoch/cci/...` + **`iCustom` 等价物**（自定义指标也要能翻译/装载）
- **交易 API（经 Broker 句柄）**：`order_send(request)->result`、`position_modify(ticket, sl, tp)`、`position_close(ticket, volume?)`、`order_delete(ticket)`、挂单全类型；支持 `magic`、`comment`、`deviation/slippage`、成交模式（FOK/IOC/Return）。
- **账户模式**：netting / hedging 切换、执行模式（market/instant/request/exchange）。

**关键：回测与实盘把同一个 SDK 对象注入策略。** 策略代码不感知 broker 实现。

### 1.2 Broker 抽象（方案的拱心石）

一个 `Broker` 接口，两套实现：

- **SimBroker（回测）**：在**现有成熟回测引擎**（`runner.py` 的 fill/cost/margin/portfolio）之上扩展，补齐：ticket 管理、部分平仓、`modify`、对冲/净持、magic、多持仓。
- **LiveBroker（实盘）**：代理到 MT 网关现有 RPC（mt4 43 / mt5 57）：`OrderSend/PositionClose/PositionModify/...`。

→ 真正实现 ADR-0012「回测/实盘统一路径」：**回测怎么跑，实盘就怎么跑**，参数与语义零漂移。这是"实盘可信"的前提。

### 1.3 事件 / 数据馈送

- **逐 tick 驱动**。
  - 回测：tick 粒度（现有 `TickSimulator` 扩展）；EA 需要真实 tick 时，导入券商 tick 历史，或由 OHLCV 按可配置模型合成 tick（明确标注假设）。
  - 实盘：网关真实 tick 流 → `on_tick`。
- 由 tick 派生 timeframe bar 事件 → `on_bar`；`on_timer` 由调度器驱动。

### 1.4 执行 & 风控网关（Go，金钱安全边界）

**所有下单意图（sim 或 live）在到达 broker 前，必须过这道 Go 风控门**：

- 逐账户：最大手数、最大持仓数、最大敞口、**日亏 / 回撤熔断**、品种白名单、杠杆上限、下单频率限制、重复单防护。
- 全局 kill-switch + 每用户 autotrade 开关（已有，扩展）。
- 保证金预检。

**真正的实盘安全活在这里，与策略对错解耦**——即使策略疯了，坏单也到不了市场。

### 1.5 沙箱 / 隔离（安全边界下移）

从"语言级"（RestrictedPython）下移到"OS/VM 级"：

- 每个策略跑在专用 worker：**非 root、只读 rootfs、断网（net namespace）、seccomp-bpf 系统调用过滤、cgroup 限 CPU+内存+PIDs、无宿主挂载**。
- 最强档：对敌对多租户用 **gVisor / Firecracker microVM** 每租户隔离。
- 预热 worker 池降延迟 + 重启策略（现有 `live_sandbox.py` 模式可复用）。
- **因为爆炸半径被内核/VM 锁死，反而可以放开完整 Python（numpy/pandas 等）→ 比今天既更安全又更有能力。** RestrictedPython 降级为代码 lint，不再充当安全边界。

### 1.6 翻译层（MQL → SDK）

两阶段 + 校验闭环：

1. **确定性 Transpiler**：用真实 MQL4/MQL5 文法做 AST，机械映射构造（`OnTick→on_tick`、`OrderSend→broker.order_send`、`iMA→indicators.ma`、`ArrayInitialize`、`OrderSelect` 循环 → 持仓迭代…）。处理机械的 ~80%，**确定、零幻觉、可审计**。
2. **LLM 补全**：只处理 transpiler 标记的缺口（`iCustom` 自定义指标、复杂指针/字符串、语义歧义）。LLM 面向**精确 SDK 规格 + few-shot**，以 transpiler 产物为脚手架。
3. **行为校验 harness**：把翻译后的策略在回测中跑，与同一 EA 在 MT 的**金标准参考运行/录制成交**做**行为 diff**（开平仓时点、方向、手数、盈亏曲线）。**这一步才真正闭合"翻译对不对"。**
4. **覆盖度报告**：明确告诉用户哪些 MQL 特性无法翻译（DLL/WebRequest/GUI）以及如何被桩化。

产物是**人类可读、可编辑**的 Python SDK 代码——用户可直接微调，这是 Python 作为目标语言的重要优势。

## 2. 语言 / 运行时抉择（真正的分叉，给出推荐）

| 维度 | Python SDK（推荐） | 确定性 MQL→IR + 自研 VM（Go/Rust） |
|---|---|---|
| 翻译友好度 | 最佳（LLM 友好 + 产物可读可改） | 最差（IR 不可读，LLM 难） |
| 保真度 | 高（语义由 SDK/Broker 决定） | 高 |
| 安全 | 靠 OS 沙箱（成熟做法） | 构造即安全（无 RCE） |
| 性能（tick 回测） | 需补偿（编译版 tick-core / 向量化） | 原生快 |
| 工程量 | 中（复用现有引擎+生态） | 极大（写正确的 MQL 编译器+VM） |
| 用户可改 | 是 | 否 |

**推荐：以 Python 为策略 SDK 语言，引擎编排用 Go，安全靠 OS 沙箱。** 理由：它是最佳翻译目标（可读、可改、LLM 友好），唯一短板（tick 回测性能、安全）已有成熟解法——

- 性能：①纯指标型策略走向量化预计算；②事件型 EA 的 tick 热循环用 **Rust/Cython tick-core**（引擎驱动、策略回调），或在"成本不设限"下接受"慢但正确"的 tick 回测；③实盘是实时速率，性能无忧。
- 安全：OS/VM 沙箱解决，与语言无关。

**备选（保留）**：若未来 Python 在性能/安全上被证明不足，再上"确定性 MQL→IR + 自研 VM"——构造即安全、原生速度、无 RCE，但工程量巨大且牺牲可读性，作为后手而非首发。

## 3. 分阶段路线（速度非优先，但分期降风险）

- **Phase 0 — 契约先行**：冻结 SDK 规格 + Broker 接口 + 风控门协议（先定接口，再写实现）。手工把 3~5 个代表性 EA（单进单出、网格、马丁、多单对冲、带自定义指标）按 SDK 写一遍，验证 SDK 表达力足够。
- **Phase 1 — SimBroker + SDK**：在现有回测引擎上实现 SimBroker，跑通手工移植的 EA，建立回测保真度基线。
- **Phase 2 — 翻译层**：确定性 transpiler MVP + LLM 补全 + 行为校验 harness；建金标准 EA 语料。
- **Phase 3 — 实盘**：LiveBroker over MT 网关 + 风控网关 + OS 沙箱；paper↔live↔backtest 三方一致性测试。
- **Phase 4 — 上线**：kill-switch、灰度（canary 账户、小手数）、全链路可观测、回测/实盘漂移看板。

## 4. 复用 / 新建 / 退役

- **复用**：回测引擎核心（fill/cost/margin/portfolio）、MT 网关 RPC、调度引擎、前端策略页。
- **新建**：Strategy SDK、Broker 抽象、MQL transpiler、风控网关、OS 沙箱、行为校验 harness、自定义指标库。
- **退役/改用**：signal-dict 实盘路径（替换为 Broker 模型）、RestrictedPython 安全边界（降为 lint）、factor DSL（保留给"AI 生成简单策略"档，不用于 EA）、production-block 标志（移除或重定义）。

## 6. 关键风险与对策

| 风险 | 对策 |
|---|---|
| MT 语义边角（requote/滑点/swap/周末跳空/部分成交/stops·freeze level） | 在 Sim 与 Live **两个 broker 中以相同规则建模**，并纳入金标准校验 |
| `iCustom`/自定义指标 | 建指标库 + 支持把自定义指标本身也翻译进 SDK |
| 对冲 vs 净持（MT4 hedging / MT5 两者） | SimBroker 必须同时支持两种持仓模式 |
| 真实 tick 数据可得性 | 接入券商 tick 历史；缺失时用明示假设的合成 tick |
| 行为校验需要 MT 参考运行 | 用 MT Strategy Tester 报告 / 实盘录制成交建金标准库 |
| DLL/WebRequest/文件 IO/GUI | 明确列为不支持并桩化，覆盖度报告告知用户 |

---

## 7. 一句话总结

**不要在"signal 模型"上修补，也不要纠结 DSL/ONNX。最优解 = 忠实复刻「事件模型 + 券商语义」的统一 Strategy SDK + 双实现 Broker（回测/实盘同码）+ Go 逐单风控门 + OS 级沙箱；翻译用「确定性 transpiler + LLM 补全 + 行为校验」三件套。** 语言选 Python（最佳翻译目标），性能与安全用编译版 tick-core 和 OS 沙箱补齐；自研 VM 作为后手。
