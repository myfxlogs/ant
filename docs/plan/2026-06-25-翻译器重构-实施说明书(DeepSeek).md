## 0. 背景：为什么必须重构（实证结论）

2026-06-25 实测当前翻译器（5 个样本 EA）：

- **Line-by-line 正则路径**（`tools/mql_transpiler/transpiler.py`）：**5/5 产物不编译**（MQL `//` 注释被原样吐进 Python），但 `confidence` 报 0.85–1.00。
- **手写 AST/RD 路径**（`ast_transpiler.py` + `ast_parser.py`）：**4/5 直接崩溃**（`UnaryOp` 在 `ast_transpiler.py:458` 使用但未导入），仅 1/5 编译。
- **致命设计缺陷**：`confidence = matched/(matched+gaps)` 是**虚荣指标**，只衡量"认出多少构造"，不衡量产物是否合法/正确 → 出现"100% 置信 + 非法代码"。测试只验子串（`assertIn`），从不 `ast.parse`，于是腐烂瞒过 CI。
- **架构假象**：所谓"RD parser"并不独立——`ast_transpiler.py:377-399` 的 `_needs_line_fallback()` + `_get_line_transpiler()` 把表达式等难点**甩回正则**。难的 20%（表达式/作用域/优先级）正是没真正做的部分。

结论：这不是"80% 完成待打磨"，而是**产出非法代码却报高置信**，比没有更糟（误导）。按 `CLAUDE.md` 红线，**不做止血、直接重构到最优解**。

## 1. 北极星（决策 D8）

**翻译器的唯一可信度量 = 编译通过 + 行为对齐，而非"模式命中率"。**

- 正确性由 **parser 无关的质量门** 外部强制：任何方法翻译的产物，必须过 `ast.parse` + SDK import 冒烟 + 行为对齐 harness。
- 一旦两道门立起来，**parser 选择从"架构决策"降级为"可逆的工程权衡"**。
- 收敛到**单一 parser**，确定性 AST→codegen 覆盖机械部分，LLM 仅做缺口填充且**必须过同一道门**。
- 彻底退役并行实现（正则 fallback / 多 parser），遵守 Reuse Preflight、反 shelf-ware。

---

## 2. parser 路线：RD-first，但带量化切换触发器

采用 **手写 RD parser 优先** 路线，**前提是满足第 3 章四条不可退让条件**。理由：正确性由外部 gate 保证，故 RD-first 不构成"妥协最优解"——它是可逆的工程权衡，而非牺牲正确性。

**为什么不立即上 tree-sitter**：无现成 `tree-sitter-mql`；但 **MQL4 ≈ C / MQL5 ≈ C++ 子集**，故"从零写语法"的成本假设不成立——见 T0 强制评估 fork `tree-sitter-cpp`。

---

## 3. 不可退让条件（违反任一条 = 重构失败，退回重做）

### C1 — 立即无条件删除正则 fallback
RD parser 必须**独立站住**。解析不了的构造 = **硬 GAP 节点 → LLM 过门**，**绝不准静默甩回正则**。这是"RD 架构是否正确"的试金石：离开正则拐杖还能不能达标。
- 删除 `ast_transpiler.py` 中 `_get_line_transpiler` / `_needs_line_fallback` / `_transpile_expr_stmt` 的正则回退分支。
- 退役 `tools/mql_transpiler/transpiler.py`（整文件，不许标 legacy 保留）。

### C2 — 质量门 + 行为对齐 harness 先行（parser 无关）
**先建门，再改 parser**，用门约束任何 parser 实现。
- 质量门：① `ast.parse(output)` ② SDK `import` + 策略类实例化冒烟 ③ lint（禁 `//` 残留、禁裸 MQL 函数名残留）。
- 行为门：用 Phase 0 已手写的 **5 个 SDK 参考策略**作 oracle，给定 golden bar 序列，断言"译出 Python 的下单信号逐 bar == 手写参考"。
- **重定义 `confidence`**：两门皆过 = HIGH；否则 LOW（走 LLM/人工）。**删除 `matched/total` 算法**（`ast_transpiler.py:188-193`、`transpiler.py:374-378`）。任何不编译产物一律判 LOW，绝不报高分。

### C3 — 预先写死可量化的 tree-sitter 切换触发器
不靠"手感"。满足**任一**触发器即强制切换 tree-sitter（fork `tree-sitter-cpp`）：
- 在 ≥ 20 个真实世界 EA 的 corpus 上，**无 fallback 的 clean-parse 率 < 90%**；
- 表达式优先级/结合性正确性测试**不达标**（运算符优先级 golden 用例失败）；
- RD parser 解析回归**累计 > 3 次**（同类 bug 反复）；
- 维护单个语法缺口的补丁需改动 > 200 行 RD 代码。

### C4 — 先评估 fork tree-sitter-cpp 的真实成本
在投入 RD 补齐前，**先花半天**评估：fork `tree-sitter-c`/`tree-sitter-cpp` + 加 MQL 内建/交易 API 的真实工作量。若显著低于补齐 RD，**直接走 tree-sitter**（C3 触发器形同立即触发）。结论写进 PR，用 `NEEDS-DECISION:` 标注供人类拍板。

## 4. 任务拆解（契约先行，逐个跑绿）

### T0 — fork 成本评估（C4）
- **产出**：一页评估——fork tree-sitter-cpp 改 MQL 的工作量 vs 补齐 RD（含正则退役）。`NEEDS-DECISION:` 给人类。
- **DoD**：有量化对比；人类拍板 parser 路线后再进 T1。

### T1 — 质量门 + 行为对齐 harness（C2，parser 无关，最先做）
- **产出**：`transpile` 端点与测试强制过 `ast.parse` + SDK import 冒烟 + lint；行为对齐 harness（5 样本 golden 信号 diff）。
- **DoD**：当前任意产物跑过门即如实判 LOW（能复现"高置信非法代码"被门拦下）。

### T2 — parser 补齐 / 切换（依 T0 结论）
- **RD 路线**：补齐表达式（一元/三元/优先级）、作用域、`#define/#property/#include`、MQL4/5 交易 API 差异；**修 `UnaryOp` 未导入**；**删除正则 fallback（C1）**。
- **tree-sitter 路线**：fork cpp 语法 + MQL 扩展，`parse_mql` 返回真实树（替换 `tree_sitter_parser.py:217-229` 的死实现）。
- **DoD**：5 样本无 fallback 全解析为完整 AST；解析失败显式报节点位置，无 silent-drop。

### T3 — 确定性 codegen
- **产出**：canonical AST → SDK codegen。**复用** `mappings_generated.py` / `rpc_params_generated.py`（proto 派生，已验证资产，禁止重造）。
- **要求**：金额/价格全程 `Decimal`；MQL 逆序索引语义保留。
- **DoD**：覆盖 ~80% 机械构造；无法映射节点 → 结构化 GAP span（带源位置 + 原因）。

### T4 — LLM 缺口填充（门后，保可审计）
- **产出**：仅对 GAP span 调 LLM，回填后**必须过 T1 两道门**；记录哪些 span 由 LLM 生成（审计留痕）。
- **DoD**：确定性核心仍可审计；LLM 产物不达标则拒绝、不静默放行。

### T5 — 测试重写
- **产出**：删除/重写 `tests/test_transpiler.py` 全部 `assertIn(子串)` 断言，改为 `ast.parse` + 运行 + 行为对齐。
- **DoD**：测试能捕获"高置信非法代码"这类回归。

## 5. 退役清单（删除，不许标 legacy 保留）

- `tools/mql_transpiler/transpiler.py`（正则 line-by-line）。
- `tools/mql_transpiler/ast_parser.py`（若走 tree-sitter）/ 或保留并删其正则依赖（若走 RD）。
- `tree_sitter_parser.py` 中 `parse_mql` 永远返回 None 的死实现 → 真实实现或整体删除（依路线）。
- `strategy_connect.py` 中"AST 失败退 line-by-line"的双路兜底 → 单路。

> 每项在 PR 标 `RETIRE: 删除<X>`，并确认无其它调用方（Reuse Preflight）。

## 6. 给 DeepSeek 的硬约束

- **一个 parser，一份实现**；禁止保留正则/第二 parser 作"备份"。并行实现 = 漂移 = 违规。
- **正确性是门，不是分数**；不编译/行为不对齐的产物视为失败产物。
- **复用 proto 派生映射**，不重造。
- **遵守 Reuse Preflight**：动工前 `bash scripts/cap.sh transpile|parse|mql`，PR 标 `REUSE:`/`NEW:`。
- **MT 语义/parser 路线不确定就停**：用 `NEEDS-DECISION:` 标注，绝不猜。
- **翻译正确 ≠ 交易安全**：译出代码仍走 SDK→Broker→风控门，职责分离。

---

## 7. 整体验收

- 5 样本 EA：单一 parser 全解析（无 fallback）→ codegen + LLM 填充 → **全部编译通过 + 行为逐 bar 对齐手写参考**。
- 正则/冗余 parser 已删除，仓库只剩单一管线。
- `confidence` 反映编译+行为，能拦"高置信非法代码"回归。
- C1–C4 四条不可退让条件全部满足，切换触发器已写入文档。
