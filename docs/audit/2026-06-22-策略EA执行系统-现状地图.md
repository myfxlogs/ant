# 现状地图：策略 / EA 执行系统

> **日期**：2026-06-22
> **范围**：EA 翻译 → 沙箱执行 → 回测 / 实盘下单 / 调度 全链路勘察（只读，未改动代码）
> **目的**：在为"完全替代 MetaTrader 跑 EA"这一目标动手前，先建立可靠的现状基线，区分"已实现 / 原型 / 货架闲置"，并记录文档与代码的漂移点。
> **方法**：基于实读代码与文件/行号证据，非文档转述。

---

## 一、真正在跑的执行引擎（最大疑点澄清）

| 引擎 | 文档宣称 | 代码实际状态 |
|---|---|---|
| **Python signal 沙箱** | "研究专用" | **唯一真正接入生产 / 回测 / 实盘的运行时** |
| **factor DSL** (`backend/internal/factor/dsl/`) | "生产路径" | **已建成 + 有 Go/Python 对齐测试，但全仓库只有它自己的测试 `import` 它，零生产调用** |
| **ONNX** | "生产路径" | 仅存在于 `strategy-service/.../research/ant_research/model/`（LightGBM 训练 + 导出），**不在实盘 / 回测链路** |

**结论**：`strategy-service/app/engine/sandbox.py:6-7` 写的"生产走 DSL+ONNX、不跑任意 Python"是**纸面决策，从未落地**。同时实盘 Python 路径（`ExecuteLive` / `LiveWorker`）**并不受** production-block 限制——即今天的实盘策略其实就是在跑 Python。DSL / ONNX 是"货架上的库"。

证据：
- `backend/internal/factor/dsl/`（lexer / parser / ast / compile / operators）只被 `alignment_test.go` 引用；全仓库 `grep "internal/factor/dsl"` 仅命中该测试。
- ONNX 仅命中 `research/ant_research/model/__init__.py`（训练 / 导出）与 sandbox.py 的注释文字。
- `ExecuteLive` / `LiveWorker`（`strategy-service/app/routes/live_execute_connect.py`、`engine/live_sandbox.py`）无 `is_production_mode()` 检查。

## 二、回测链路（成熟，质量较高）

`strategy-service/app/engine/runner.py` — tick 驱动主循环，已实现：

- 挂单队列（limit / stop / stop_limit）+ 到期清扫、SL/TP 检查、保证金强平、隔夜 swap
- 信号动作集丰富：`buy / sell / close / cancel_pending / *_limit / *_stop`，单仓 / 多仓模式、多空方向过滤
- **跨 bar 持久化 `runtime` dict**（专为网格 / 马丁等有状态 EA，`runner.py:147,233`）
- 两种模式：逐 bar `run(context)`（`StrategyRunner`）与向量化 `run_dataframe(df, params)`（`DataFrameStrategyRunner`）
- 配套模块 `fill / portfolio / cost / margin / market / metrics` 均已接线

这部分是整个系统**最扎实**的资产。

## 三、实盘链路（薄原型，多处缺口）

闭环：
```
schedule_engine.go (定时器)
  → RunLiveStrategy (live_runner.go)
  → 订阅 bar 流
  → 每 bar 调 ExecuteLive (Python LiveWorker 池)
  → dispatchLiveSignal
  → mthub.PlaceOrder (live) / PaperEngine (paper)
```

**关键缺口（直接导致"翻译后实盘跑不对"）**：

1. **实盘 context 不回传持仓 / 权益**：`buildLiveContext`（`backend/internal/connect/strategy/live_runner.go:129-163`）只填 OHLCV + params，`position / positions / equity / balance` 全空。
   → 策略里 `context['position']` 永远 `None`，"已有仓位就不再开"这类 EA 逻辑在实盘**完全失明**，会每根 bar 重复开单。

2. **只映射了 `buy` / `sell`**：`signalToSide`（`live_runner.go:251-260`）对 `close / close_all / 挂单` 一律返回 0 → **静默丢弃**。注释说"由 OMS 处理"，但**实盘路径里没有任何 OMS 在处理它们**。回测支持的丰富动作集，实盘只落地了裸市价买卖。

3. **没有逐单风控门**：signal 的 `volume` 直接进 `PlaceOrder`，**无**最大手数 / 最大持仓 / 回撤熔断 / 品种白名单 / 频率限制。唯一的闸是 schedule 级的 `autoTradeEnabled(userID)` 粗粒度开关（`schedule_engine.go:175`）。

## 四、调度 / 自动交易

`backend/internal/connect/strategy/schedule_engine.go` — 定时器驱动、零轮询：

- `GetDueSchedules` → `dispatch` → `runOne` → `RunLiveStrategy`
- `dispatch` 中 **Mode 硬编码为 `"live"`**（`schedule_engine.go:220`），策略代码取自 `tpl.PythonSkeleton`

- `RunLiveStrategy` 阻塞式订阅 bar 流，直到 ctx 取消

## 五、EA 翻译（确定性损坏）

`TransformCode`（`backend/internal/connect/ai/code_assist_handler.go:200-219`）的 LLM 提示词让模型生成**运行时不存在的 class API**，与真实运行时全面错配：

| 维度 | 提示词要求生成的（不存在） | 运行时真正支持的 |
|---|---|---|
| 入口 | `self.on_bar(bar)` | `def run(context):` |
| 下单 | `self.buy()/self.sell()/self.close_all()` | `return {"signal":"buy","volume":...,"stop_loss":...}` |
| 持仓 | `self.has_position()/self.position_side` | `context['position']` / `context['positions']` |
| 行情 | `bar.close`（对象） | `context['close']`（numpy 数组） |
| 指标 | `self.sma/ema/rsi/bollinger/macd/atr` | 模块级 `iMA/iRSI/iBands/iMACD/iATR` |
| 参数 | `@param` 装饰器 | `# @param` 注释 + `params.get('x')` |

→ **翻译结果基本 100% 校验失败**（`sandbox.py:143` 要求必须有 `run(context)` 或 `signal`）。
另有长度限制冲突：翻译允许 64KB（`code_assist_handler.go:175`），但 `sandbox_scan.py:24` 拒绝 >10000 字符。

## 六、沙箱安全姿态

6 层叠加，但**真正隔离只有多进程**：

1. AST 白名单（`sandbox.py:validate_strategy_code`）
2. 独立静态扫描器（`sandbox_scan.py`，与第 1 层规则大量重复）
3. RestrictedPython 编译（可绕过、维护停滞）
4. 精选 globals
5. marshal 字节码缓存
6. `multiprocessing.spawn` 子进程 + 管道 IPC + `RLIMIT_AS` + 重启策略（`live_sandbox.py`）

- 真正提供隔离的只有第 6 层；第 3 层 RestrictedPython + threading.Timer 超时（代码自承对 C 扩展无效，`sandbox.py:357-363`）属于"虚假安全感"。
- **缺真正的 OS 级隔离**：子进程仍共享容器的网络 / 文件系统 / 内核，仅限制了内存。无 seccomp、无断网、无只读 FS、非 root 化、无 CPU cgroup。

## 九、总体判断

- **能用**：Python 回测引擎（成熟）、策略库 / 模板 / 调度 UI、定时调度框架。
- **原型 / 半成品**：实盘下单链路（仅裸市价、无持仓回传、无逐单风控）、EA 翻译（API 错配损坏）。
- **货架闲置**：factor DSL、ONNX 研究管线。
- **本质矛盾**：要"完全替代 MT 跑 EA"，缺的不是沙箱花样，而是：
  1. 翻译目标对齐真实运行时；
  2. 实盘把回测已有的完整下单语义 + 持仓回传补齐；
  3. 一道真正的逐单风控门。
