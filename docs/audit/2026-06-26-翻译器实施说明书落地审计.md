## 2. 缺陷（必须修复）

### D1 — 行为对齐 harness 建了但没接上测试

**严重度**：P0 — 北极星未覆盖

`behavioral_harness.py`（521 行）实现了 `RecordingBroker`、`StubContext`、`SignalComparator`、`run_strategy_with_recording()`，但 `test_transpiler.py` 中的 `TestBehavioralStructure` 只做结构断言（`assertIn("self.broker.order_send(", output)`），**从未调用 `SignalComparator.compare()`**。

实施说明书 §1 北极星："翻译器的唯一可信度量 = 编译通过 + **行为对齐**"。编译通过有测试覆盖，行为对齐没有。

**要求**：新增端到端测试，对每个 fixture 执行：MQL source → parse → codegen → quality gate → `run_strategy_with_recording()` → `SignalComparator.compare(ref, trans)` → 断言 `result.match == True`。

### D2 — `FIXTURE_ORACLE_MAP` 空壳

**严重度**：P0 — oracle 映射断线

`behavioral_harness.py:501`：

```python
FIXTURE_ORACLE_MAP: Dict[str, type] = {}
```

`_lazy_load_oracles()` 在 `:503-520` 定义了，但**没有任何调用方触发它**。即使 D1 的测试写了，oracle 也加载不出来。

**要求**：在 `run_strategy_with_recording()` 或测试 setup 中调用 `_lazy_load_oracles()`，确保 `FIXTURE_ORACLE_MAP` 被填充。

### D3 — `SignalComparator` 用 set 比较丢失顺序和重复

**严重度**：P0 — 行为比较逻辑错误

`behavioral_harness.py:353-358`：

```python
ref_set = set(ref_sigs)
trans_set = set(trans_sigs)
matching = ref_set & trans_set
```

把调用序列变成**集合**，同一 bar 内 3 笔相同参数的 `order_send` 会被折叠成 1。策略行为的时序、重复交易、多笔操作差异**完全无法检测**。

**要求**：改为有序 list + 计数比较。两个 `Counter` diff，或逐 bar 按 `bar_signals` 有序比对。

### D4 — `GoldenBar` 用 float 而非 Decimal

**严重度**：P1 — 违反项目红线

`behavioral_harness.py:67-74`：

```python
@dataclass
class GoldenBar:
    open: float
    high: float
    low: float
    close: float
```

CLAUDE.md / ADR-0020 §5.3 红线："金额/价格全链路用 Decimal 或定点整数，禁止 float"。行为 harness 喂 float 数据给策略，可能掩盖 Decimal 精度相关的行为差异（如 `Decimal("1.10000") != 1.1`）。

**要求**：`GoldenBar` 字段改为 `Decimal`，`ListSeries` 内部存储改为 `List[Decimal]`，golden bar 生成器同步改。

### D5 — `run_strategy_with_recording` 静默吞异常

**严重度**：P1 — 假阴性风险

`behavioral_harness.py:433-436`：

```python
try:
    strategy.on_bar(ctx.timeframe)
except Exception:
    pass
```

翻译产物如果运行时崩溃，recording 静默停止，行为比较会得出"翻译产物不下单"的假阴性，而非"翻译产物崩溃"的真实结论。

**要求**：异常改为记录到 `StrategyRecording`（如 `errors: List[Tuple[int, str]]`），`SignalComparator.compare()` 检测到 errors 时直接判 mismatch。

### D6 — KB README 仍是旧置信度体系

**严重度**：P1 — 文档与实现矛盾

（内容不变，见上文）

### D7 — `gap_kb.py` 用 JSON 做数据持久化，违反项目 JSON 禁令

**严重度**：P1 — 违反约束文档

`CLAUDE.md` 红线：`External API: ConnectRPC + SSE ONLY`（proto only）；`docs/spec/26-ai-strategy-generation.md:650` 记录了「JSON→proto 全线重构 | 消除 16 个 JSON 使用点」。项目明确在消除 JSON 使用。

但 `gap_kb.py` 仍然手写 JSON 序列化/反序列化作为 KB 存储格式：

- `gap_kb.py:18` — `import json`
- `gap_kb.py:187` — `json.load(f)` 读取 KB
- `gap_kb.py:194` — `json.dump(kb, f, ...)` 写入 KB
- 产出 `kb/unmapped_patterns.json`、`kb/gap_patterns.json` 两个 JSON 数据文件

**注**：`grammar/mql/src/grammar.json` 和 `node-types.json` 是 tree-sitter `generate` 的自动编译产物，等同于 `gen/` 目录，CLAUDE.md 豁免自动生成文件，**不违规**。

**要求**：`gap_kb.py` 的 KB 存储改为 proto 定义 + 序列化，或退而求其次用 SQLite/CSV。删除 `import json` 和两个 `.json` 数据文件。

### D6 — KB README 仍是旧置信度体系（续）

**严重度**：P1 — 文档与实现矛盾

`kb/README.md:8-13` 仍用 🟢 FULL >= 95% / 🟡 PARTIAL 85-95% / 🔴 GAP < 85% 这套"模式命中率"框架，与 C2 重定义的 HIGH/LOW 二元门**直接矛盾**。开发者读 KB 会以为 90% 命中率 = 可用，实际可能不编译。

**要求**：KB README 置信度表改为：

| Level | Meaning |
|-------|---------|
| HIGH | 编译通过 + SDK import 冒烟 + lint clean — 可进入行为对齐 |
| LOW | 任一门失败 — 不可用，需 LLM 填充或人工修复 |

Feature coverage matrix 的 Status 列同步改为 HIGH/LOW/GAP（GAP = 确定性 codegen 无法覆盖，需 LLM）。

## 3. 可优化（建议修复）

### O1 — Lint 正则对 URL 中的 `//` 可能误报

`quality_gate.py:75`：`(?<!['\"])\/\/` 的 negative lookbehind 只排除紧邻引号的 `//`，但 `"http://example"` 中 `//` 前面是 `:`，不在排除范围。建议先 `ast.parse` 提取字符串字面量，只检查非字符串区域的 `//`。

### O2 — MQL5 grammar `.so` 未编译

`grammar/mql5/` 只有 2 个文件（无 `.so`），`tree_sitter_parser.py` 检查 `mql5.so` 不存在时静默回退到 MQL4 grammar。MQL5 EA（class/OOP 语法）会按 C 语法解析，可能产生错误 CST。应在日志中 warning，或编译 MQL5 grammar。

### O3 — `connectrpc_server.py:60` HIGH→1.0 / LOW→0.0 仍用 float 字段

API 返回 `confidence: float`，消费者可能误以为 0.5 是"中等置信"。建议 proto 字段改为 `string quality_verdict` 或至少在注释中标注 binary 语义。

### O4 — 无端到端测试

没有一条测试覆盖完整链路：MQL source → parse → codegen → quality gate → behavioral harness → signal diff。各组件独立测试通过，但管线从未被串联验证。D1 的修复应同时覆盖此项。

### O5 — `gap_kb.py:110-114` 排除部分交易函数

`OrderSend`/`OrderClose` 等被排除在 unmapped scan 之外（理由是"codegen 已处理"），但如果 codegen 漏了，gap_kb 不会记录。quality gate 的 lint 会拦，但 KB 失去了追踪能力。建议移除排除列表，让 gap_kb 记录所有未映射符号。
