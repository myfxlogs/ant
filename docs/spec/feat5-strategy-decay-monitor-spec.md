# FEAT-5 策略衰减监控 + 作者发起迭代（收口 spec）

> **决策来源**：2026-08-10 产品讨论。原 FEAT-5「AI 自动迭代闭环」**重新定义**为「衰减监控(免费) + 透明徽章 + 作者发起迭代(计费)」。**不做自动迭代、不做退款**。
> **关联**：registry FEAT-5、`decay_detector.go`（已有）、ADR-0028 §5.4「诊断免费 / 修复收费」、ARCH-4⑥ 成交归因（衰减数据源）。
> **状态**：🏗 待施工。**日期**：2026-08-10

---

## 1. 决策（讨论结论，施工方遵守）

1. **自动迭代 → 作者手动发起**。策略是作者 IP；平台不能自动改作者代码并发布（IP + 责任 + token 成本不可控）。
2. **衰减监控 = 诊断，免费、确定性**（同防线性质；`decay_detector` 已有）。衰减 → **通知 + 透明徽章**，**不自动调 agent**。
3. **作者发起迭代**：agent（LLM）→ **计费作者 token**（credit PreHold/Settle）；手工改代码 → 免费。复用 ADR-0028 §5.4「修复收费」。
4. **不做退款**。pre-revenue 退款是死路（钱已分作者，无从退）。买家保护 = **信息透明**（购买前看验证战绩 + 购买后衰减徽章 + 停止新购），自担风险（同 MQL5 Market 买 EA）。
5. **钱模型（一次性购买 / 订阅 / 按盈利分成）待首批真实收入 + decay 数据后定**，现在不锁。

## 2. 目标 / 非目标

**目标**：① 衰减监控真正跑起来（对已发布 + 实盘策略）；② 衰减 → 通知作者 + 买家 + marketplace 徽章 + 停止新买家购买；③ 作者发起迭代入口（agent 计费 / 手工免费）→ 新版本 → 已订阅买家自动得新版。

**非目标**：❌ 退款 / decay 退款；❌ 自动迭代（作者必须发起）；❌ 锁定钱模型；❌ 按盈利分成（北极星，见 §6，暂不设计）。

## 4. 验收 + 对抗证明

- 已发布 + 实盘跑的策略，衰减（3 信号 ≥2：Sharpe/胜率/回报）→ 状态更新 + 作者/买家收通知 + marketplace 徽章 + 新买家购买被拦。
- 作者"AI 迭代" → credit 扣费 + 新版本；已订阅买家自动得新版。手工改 → 免费 + 新版本。
- **对抗证明**：删停购 gate → 衰减策略可被新买家买（红）；删 credit 扣费 → 作者 agent 迭代不扣费（红）；删通知 → 作者/买家不知情（红）。

## 5. 明确不做

- **退款 / decay 退款**：pre-revenue 死路。买家保护靠透明，不靠退钱。
- **自动迭代**：作者必须发起（IP + 成本 + 责任）。
- **钱模型锁定**：等真实收入 + decay 数据。

## 6. 北极星：按盈利分成（暂不设计，记未解难题）

长远理想模型 = 买家不预付，按"用策略赚的盈利"抽成给作者（衰减 → 不赚 → 作者自动少赚，**无需退款，激励对齐**）。**但有未解难题，暂不设计**：

- 平台**非经纪商**，**无法把控买家资金 / 持仓盈亏的现金流**（买家在自带 broker，盈亏在 broker 账户，不在平台）。
- 若"预付费到平台再按盈利分"，**预存多少？盈利上不封顶、预存有限** → 机制设计难。
- **地基已铺**：ARCH-4⑥ 归因能算"每策略给买家赚多少"；但**资金流 / 托管 / 结算**需经纪商资质或另寻方案。
- **暂不考虑**，等有真实收入 + 规模再回来讨论。
