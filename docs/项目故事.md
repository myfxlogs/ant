## 一、一句话故事

AlphaForge 是一个**策略市场**：MQL 开发者把策略交进平台编译成字节码，AI 帮它回测、挑错、迭代；散户购买后可一键挂到自己的 MT4/MT5 实盘账户上跑，平台全程留痕真实战绩并抽成。代码不出平台、战绩公开透明、AI 持续进化——对标 MQL5 Market 的三点差异化。

商业模式已定死（AGENTS.md §1）：平台订阅 + 策略抽成 15-30%。不做自营、不做跟单、不碰用户资金、不拿牌照。

## 二、系统分层

```
┌─ 前端 React+TS（workspace 工作台 / marketplace 市场 / admin 后台 / wallet）
│     ConnectRPC（请求-响应）+ SSE（所有实时推送的唯一通道）
│
├─ API 层 backend/internal/connect/<域>/   —— 56 个 ConnectRPC service 生成物
│     interceptor 链：Sentry→SSE keepalive→SSE 限流→auth(JWT)→admin→rate-limit→OTel
│
├─ 领域服务层 backend/internal/*
│     ├─ agent/ai        Agent 引擎：策略生成、AI 门禁管线（DSR/MC/OOS/lookahead）
│     ├─ connect/strategy 策略执行宿主：LiveRunner/回测 worker/调度引擎/mutation 协调
│     ├─ mthub           订单枢纽：幂等门/对账门/broker 注册表/事件 broker 簇
│     ├─ oms             订单管理：16 态状态机、FillModel、P&L 双轨归因
│     ├─ mdgateway       行情网关：mtapi 适配器（mt4/mt5 分立）→归一化→落库+广播
│     ├─ marketplace     市场：发布/购买/冻结结算/实盘绩效采集
│     ├─ risk+risksvc    11 规则闸门 + 平台聚合风控
│     ├─ repository      PG 数据访问（sqlc 生成物+手编仓储混用）
│     └─ service/systemai 等   系统服务（计费、配额、账户同步）
│
├─ 策略技术栈 backend/{strategy,tools/mql2go}
│     strategy/sdk       策略接口契约（Strategy/Context/Broker/IndicatorSet）
│     strategy/runner    Go 策略运行器（live/回测共用执行骨架）
│     strategy/backtest  回测引擎（bar 重放、撮合、挂单触发、净值曲线）
│     tools/mql2go       MQL/Python→tree-sitter AST→IR→字节码；interp VM 执行
│
├─ 基础设施
│     PostgreSQL 18（唯一持久层，256 个 migration）· Redis（缓存/幂等/限流）
│     NATS JetStream（内部事件总线+trade event store）· Sentry/OTel/Prometheus
│
└─ 外部边界：mtapi.io gRPC 代理 → 用户自选 MT4/MT5 经纪商（平台不碰资金）
```

## 三、核心管线（按数据流）

### 3.1 行情引入管线 `mdgateway`

`mtapi 订阅 → adapter/mt4|mt5（两适配器代码不共享，仅 mdtick DTO 共享）→ normalizer（去重/质量门/quote-stuffing 检测/bar 聚合）→ 双通道输出：PG 分区表（market_data，启动即 EnsureMarketDataPartitions）+ 内存 broker 簇（barBroker/tickBroker/tradeBroker）→ SSE 推前端 + 喂 LiveRunner`。

断连兜底：circuit_breaker + auto_reconnect + snapshot 持久化（PositionSnapshotPersister）+ DLQ writer。ADR-0010。

### 3.2 策略编译管线 `mql2go`

`MQL4/MQL5 或 Python 源码 → tree-sitter AST → IR（语言中性，为加密市场预留）→ bytecode → interp.VM 执行`。安全边界：MaxSourceSize 限制 + panic 恢复（ADR-0023）。编译产物缓存落 `imported_strategies.bytecode`，boot 时 `MarshalBytecode` 复用免重编。SEMANTICS 系修复史（VM-COMPILER-SEMANTICS-1 等）保证 MQL 语义：timeseries、隐式变量、local array、enum 编号等均逐案实证。

### 3.3 回测管线

`前端参数 → ExecuteBacktest RPC → backtest worker：策略源→CompileMQL→VMRunner+Engine（bar 重放）→ SimBroker 撮合（限价/止损单触发按 MT4 语义：挂单只在 fill 时计佣占保证金）→ FillModel（点差+滑点+手续费强制非零默认，防"过于好看"回测）→ PnLCalculator 双轨（Gross/Net 都出）→ 结果落 PG + SSE 通知`（ADR-0028 可靠性验证分层）。

### 3.4 实盘执行管线（最重的一条）

```
LiveRunner 订阅 bar/tick/trade broker（push-first，零轮询）
 → session.SendEvent → VM 内策略 OnBar/OnTick/OnTrade
 → 信号 emit（15 个 builtin emitSignal，syncDispatch 同步派发）
 → dispatchByAction：open/close/modify/cancel/cancel_all
 → mutation_coordinator（mutationSpec：提交+verifyReadAfterWrite+barrier 等待）
 → mthub：idemGuard（Redis 幂等）→ reconcileGate → killSwitch → brokerReg → mtapi 下单
 → broker 事件回流 → eventBroker → OMS 16 态机推进 → trade_records 写台账（hash 链）
 → accountSyncSvc → SSE 推 profit/position/snapshot
```

关键机制：
- **mutation barrier**：下单后等 broker 确认事件，outcome 三态（confirmed/rejected/unknown）；unknown 触发对账而非重试（防双单）。
- **OMS 16 态机**（ADR-0012，对齐 NautilusTrader）：NEW→VALIDATED→RISK_APPROVED→SUBMITTED→WORKING/PARTIALLY_FILLED→FILLED/CANCELLED/EXPIRED/FAILED…
- **风控**：risk 11 规则闸门（首个 BLOCK 短路）+ risksvc 平台聚合 + kill switch。
- **台账完整性**：`trade_records` hash 链（entry hash = f(prev_hash, seq, 字段…)），VerifyChain 全库验链；已修 TTL 去重（879 对 CST/UTC 重复）+ epoch 幻影（3024 行）+ BALANCE 混入史。

### 3.5 Agent 生成管线 `agent` + `ai`

`用户自然语言 → generator（intent→profile→plan）→ AgentLoop 工具循环（write_strategy/compile/backtest/AI-fix）→ ai/ 门禁管线`：param_extractor、optimizers（DE/TPE/KDE）、oos_validator（样本外）、monte_carlo、deflated_sharpe、lookahead_scanner（前视偏差）、code_compliance、correlation_gate、paper_gate——策略上架前的多层验证墙。reasoning/content 双通道 SSE 流式输出。

### 3.6 市场管线 `marketplace`

`发布（publish）→ 审核 → 购买（钱包冻结结算 ADR-0029 purchase-to-live）→ 部署到买家实盘账户 → LivePerformanceCollector 实盘绩效采集 → 公开战绩回显`。钱流：订阅（Free/Pro/Enterprise）+ 购买抽成；提现/充值走 hdwallet（xpub 指纹启动校验防替换，TRON 链监控当前 CHAIN_MONITOR_ENABLED=false 暂停——TRON-SECURITY-1 业主暂缓）。

### 3.7 账户与对账管线

MT 账户 CRUD + 绑定校验（verifyMTCredentials 真连 broker）→ mdgateway 建会话 → 持仓/盈亏实时推流。`ReconciliationLoop` 周期对账：broker 真实持仓 vs OMS/trade_records；`SyncableClosedTrade` 幽灵单防线（`Unix()<=0` 守卫）。账户凭据 `platform_secrets` 密文轨（AES-GCM，master key 仅 env 引导件）。

### 3.8 配置管线（ENV-TO-PG-1，ADR-0031）

四档归位：A 引导件/B 构建期 留 env；**C 业务旋钮 21 键→system_config**（seed-once 仅缺键种入 + DB-wins overlay）；**D 秘密件 10 键→platform_secrets 密文轨**。`check-env-reads.sh` 门禁入 pre-commit——env 直读锁死 6 白名单文件。boot 链：connectPostgres→secrets→seedAndOverlay→Validate→initInfrastructure。

## 五、运维形态

- **本机=开发机**（开发/机检/push）；**sg=生产机**（pull→docker compose build→up→运行时取证），与 arb 项目共存（4C/7.8G，CPU 为最近约束）。
- 生产容器簇：backend+frontend+postgres+redis+nats+umami+prometheus+alertmanager+uptime-kuma。
- 部署唯一路径：后端 `docker compose build backend && up -d`；前端 `docker cp dist/` + nginx reload。
- 配置真相=PG；迁移随 entrypoint 自动执行（当前产库 schema_migrations 顶 `282_platform_config_secrets`）。

## 六、不变量（讨论时的"不可让步"清单）

1. **fail-closed**：实拍优先于 proto/文档；解密失败/校验失败 = 拒绝服务不降级。
2. **push-first**：事件驱动禁轮询（无事件源先定义 boot 事件）。
3. **前端零信任**：运算/校验/分页全在后端。
4. **业务配置唯一真相=PG**；秘密件永远密文轨。
5. **台账不可篡改**：trade_records hash 链，写侧规范化+全库验链。
6. **多席位纪律**：施工不自宣 done；Devin CLI 独立复审后 ✅done 才权威；交接走 git 文档。
