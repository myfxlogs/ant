# 03 · 硬约束与验收

施工方必须逐条遵守。违反任意一条 = 该任务判失败，提交前修正。

## 1. 项目硬约束（来自 AGENTS.md，零容忍）

### 1.1 协议与通信
- 对外 API 仅 **ConnectRPC + SSE**。禁 REST（healthz/readyz/livez/metrics 除外）、禁 WebSocket。
- 内部：进程内函数调用 或 NATS JetStream。

### 1.2 数据序列化
- **禁 JSON 作为数据序列化/持久化/交换格式**（`json.Marshal/Unmarshal`、`encoding/json`、`import json` 全禁）。
- 跨进程/持久化的结构化数据用 **proto 二进制**。参考 `ai_strategy_templates.parameter_slots []byte` 模式。
- 豁免：自动生成产物（`gen/`）、PG `JSONB` 列（由 DB 管理）。
- **本重构特别注意**：Task 3 的参数存储用 `bytea` + proto，不得用 JSON。

### 1.3 精度
- 价格计算用 `decimal.Decimal`（Go），禁 `float64`。
- 价格字段：PG `NUMERIC(20,8)`；时间 UTC 毫秒（`int64 ts_unix_ms`）。
- Symbol：原始 broker symbol 即规范，不剥后缀。

### 1.4 文件与函数规模
- Go 软上限 300 行 / 函数 50 行；**硬红线 Go > 450 行必须拆**。
- TS 软上限 250 行；**硬红线 TS > 375 行必须拆**。
- 按语义域拆分优先（CRUD / 生命周期 / 实体类型）。
- 豁免：`gen/`、测试文件、i18n 文件。
- 检查：`cd backend && go run ./tools/check-file-lines --strict`

### 1.5 复用核对（强制）
- 动工任何新 file/function 前：`bash scripts/cap.sh <动词/别名/符号>`。
- 禁止整篇 Read `docs/CAPABILITIES.md`。
- PR 描述逐条给结论：`REUSE: <symbol> @ <file:line>` 或 `NEW: 无现成能力（已搜：<关键词>）`。
- 缺 `REUSE:`/`NEW:` 引用 = 任务判失败。

### 1.6 推送优先
- gRPC streaming + SSE 为默认。禁轮询/cron/`setInterval`/`time.Ticker`（除非数据源无推送能力且非延迟敏感）。

### 1.7 禁止因困难妥协最优解
- 遇阻回到根因，找正确修复，哪怕重构。
- 禁止快捷方式：回退代替重新生成、标 legacy 代替移除、沉默代替修复。
- **本重构特别注意**：Task 1 严禁手抄一份 builtin 清单造成与 dispatch 表二次分裂——必须单一事实源。

### 1.8 命令输出纪律
- 优先内置 Read/Grep/Glob 工具；次选 `rtk` 前缀；禁裸 `grep -rn`/`find`/`cat`/`head`/`tail`。

## 2. 架构方向红线（来自 01-架构决策.md）

| 红线 | 说明 |
|------|------|
| `interp.IR` 是唯一权威表示 | 执行/报告/导出都从它派生 |
| 报告与执行同源 | 覆盖度/盲区必须来自 `interp.Analyze(ir)`，不得回退到 `mql2go.Analyze` |
| 盲区 = 未实现的 builtin | 不是"识别器没匹配到的模式" |
| 事实源是原始 MQL | 入库存 MQL 文本，不存 gen.go 的 Go 输出，不存 IR |
| 保留 Go 原生执行路径 | `goExecutor`/`isGoStrategy` 服务原生 Go/SDK 策略，不得删除 |
| gen.go 仅导出 | 不进执行、不进持久化事实源 |

## 4. 全局回归验收（全部任务完成后）

**功能等价性**：
1. 导入一个**全支持**的 MQL EA → 覆盖度 100%，无盲区 → 启动 paper → 正常产生信号。
2. 导入一个**含缺失 builtin（如 iCustom）**的 EA → 报告精确标红该 builtin → 启动时解释器显式报错（非静默跳过）。
3. 同一 MQL 在 live 与 backtest 行为一致（都走解释器）。
4. 原生 Go/SDK 策略（AI 模板）仍正常执行（goExecutor 未受影响）。

**版本感知（MT4 / MT5）**：
4a. 导入一个 **MQL4 EA**（`OrderSend` + `OrderSelect` 遍历）→ 交易调用计入覆盖 → 启动 paper 正常下单。
4b. 导入一个 **MQL5 EA**（`CTrade.Buy` + `PositionGetDouble` + `PositionsTotal`）→ **类方法调用 `CTrade.Buy` 被计入覆盖（不出现假 100%）** → 启动 paper 正常下单/管理仓位。
4c. 一个 MQL5 EA 含**未实现的 `CTrade` 方法** → 报告精确标红该方法 → 运行时显式报错。
4d. 确认解释器未被错误拆分为 mt4/mt5 两份（语言运行时层不适用适配器不共享规则）。

**同源性验证（本重构的核心验收）**：
5. 前端报告显示"支持"的调用，运行时确实按该语义执行；报告"标红"的，运行时确实失败。**预览 == 执行。**

**持久化**：
6. 导入策略 → 重启服务 → 用 strategyID 取回原始 MQL → 重新编译 IR → 启动成功。

**降级确认**：
7. gen.go 的 Go 输出在 UI 标注"仅供导出"，且启动策略时后端走 IR 而非 gen.go 编译（日志/断点确认）。

## 6. 升级/求助路径

- 若 Task 0 发现解释器 builtin 缺口过大（核心交易/指标缺失），**先补齐缺口再推进 M3 的执行收敛**，但 M1（报告同源）不受影响，应立即推进——这恰恰是让缺口"可见"的手段。
- 任何与本规格冲突的既有代码/架构，以本规格为准（已获最终决策授权）。如发现规格本身有事实性错误，停止并回报，不得自行偏离方向。
