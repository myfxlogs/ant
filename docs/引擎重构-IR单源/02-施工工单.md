## Task 1 · IR 静态分析 pass（P0）

**目的**：在 `interp.IR` 上派生覆盖度/盲区/参数报告，使报告与执行同源。

**动工前复用核对**：`bash scripts/cap.sh Analyze`、`bash scripts/cap.sh IRReport`、`bash scripts/cap.sh coverage`

**文件**：
- 新建 `backend/tools/mql2go/interp/analyze.go`
- 可能需在 `interp/builtins.go` 暴露"已实现 builtin 集合"（见下）

**设计**：

```go
// IRReport 是 interp.IR 的静态分析派生报告，与执行同源。
type IRReport struct {
    Version        string
    Coverage       float64       // 已支持调用数 / 总调用数
    TotalCalls     int
    SupportedCalls int
    BlindSpots     []IRBlindSpot // 未实现的 builtin 调用点
    Params         []ParamDecl   // 直接取自 ir.Params
    Indicators     []string      // IR 中出现的指标 builtin
    ExecKind       string        // "on_bar" | "on_tick" | "on_timer"，由非空回调体推断
}

type IRBlindSpot struct {
    Builtin  string // 未实现的函数名
    Severity string // "致命"(交易/指标) | "警告"(其他) | "信息"
    Count    int    // 出现次数
}

func Analyze(ir *IR) *IRReport
```

**实现要点**：
1. 提供"已实现 builtin 集合"判定。**单一事实源**：从 `builtinTable` 的 key + 各 `switch` 的 case + `execCTrade` 的 method case 汇出 `func IsBuiltinImplemented(version, name string) bool`（或按版本拆两个集合），避免 analyze.go 与 dispatch 表二次漂移。**严禁手抄一份清单**（会再次分裂）。理想做法：把可识别的 builtin 名集中到一处常量/集合，dispatch 与 analyze 都引用它。
2. 递归遍历 `OnInit/OnBar/OnTick/OnTimer/OnDeinit/Funcs` 的所有 `Statement` 与 `Expr`，**同时收集两类调用**：
   - `ExprCall` 的 `Name`（MQL4 自由函数）
   - **`ExprField` 的方法调用**（MQL5 `CTrade.Buy` 等 `obj.method()`）——见 `eval.go evalField`：`len(e.Args) > 1` 即方法调用，方法名为 `e.Name`，对象类型取自 `e.Args[0]` 的 `ClassInstance.Name`。
   > **致命要求**：若漏掉 `ExprField`，MT5 全部交易调用对覆盖度隐形 → 假 100%。这是本任务首要正确性验收点。
3. **版本感知**：用 `ir.Version` 选择"期望 builtin 集"与严重度规则。`CTrade.*` 方法按 MQL5 类方法判定（对象类型 == `CTrade`）。
4. 用户自定义函数（`ir.Funcs`）的调用**不算盲区**（解释器会执行它们）。
5. 未实现的 builtin → 盲区。指标/交易类判"致命"，其余"警告"。严重度按版本：如缺 `PositionGetDouble` 对 mql5 致命、对 mql4 不适用。
6. `Coverage = SupportedCalls / TotalCalls`（TotalCalls 含 ExprCall + ExprField 方法调用，排除用户函数调用）。

**约束**：`analyze.go` ≤ 300 行；单函数 ≤ 50 行（遍历逻辑拆 helper）。

**测试**：`interp/analyze_test.go`，至少覆盖——
- MQL4 全支持策略 → Coverage=1.0，无盲区
- **MQL5 策略含 `CTrade.Buy` + `PositionGetDouble`** → 这些调用被正确计入覆盖（验证 `ExprField` 遍历）
- **MQL5 策略含未实现的 `CTrade.XxxUnknown` 方法** → 该方法调用点为致命盲区（验证方法调用也能判盲区）
- 含 `iCustom`（缺失）→ 该调用点为致命盲区
- 含 stub 指标 → 视策略约定为警告或信息（与 Task 0 矩阵一致）
- 含用户自定义函数调用 → 不计入盲区
- 同一未实现名在 mql4/mql5 下严重度按版本不同（如适用）

**验收**：`go test ./tools/mql2go/interp/...` 通过；盲区精确指向未实现 builtin；**MT5 类方法调用计入覆盖且能被判盲区**。
