# P6 实盘调度管线逐行审计 — 2026-08-01

## 数据流

```
LiveRunner.Start → bar/tick/trade subscription
    │
    ├── barCh → handleBar → VM.ExecuteLive → response.Signals
    ├── tickCh → handleTick → VM → response.Signals（若策略实现 TickStrategy）
    ├── tradeCh → handleTrade → VM → response.Signals（若策略实现 TradeStrategy）
    │
    ├── dispatchLiveSignal → submitOrder/mtHub.PlaceOrder
    │                        → closeAll/dispatchCloseOrder
    │                        → modify/cancel
    │
    └── 健康监控 (runner_health.go)
         ├── 30s ticker → Health() 状态检查
         ├── stale: HealthCheck → 恢复/fail
         └── dead:  ReconnectGateway → RemoveGateway → onDisconnect
```

> **注**: 核心执行管线（handleBar → VM → dispatchLiveSignal → mthub.PlaceOrder）已在 P2 审计中覆盖。本审计聚焦 live 模式特有组件。

### 2. 健康监控 (runner_health.go)

✅ 30s ticker 周期——合理。
✅ 状态分级: stale（>5min无数据）→ HealthCheck → dead。
✅ Dead 处理: ReconnectGateway → 失败则 RemoveGateway → onDisconnect。
✅ Stale 并发检查: WaitGroup + channel 收集结果。

| 行 | 严重度 | 问题 |
|----|--------|------|
| 100-105 | 🔴 HIGH | **goroutine 无 panic recovery + 无超时**。`HealthCheck` panic 时 `wg.Done()` 不被调用 → `wg.Wait()` 永久阻塞 → 整个 healthMonitor goroutine 死锁。此外 HealthCheck 无 timeout——网络故障时可能永远不返回 |
| 79 | 🔵 LOW | `time.Sleep(100 * time.Millisecond)` ——用途不明。注释缺失 |

### 3. Shadow Verifier (shadow_verifier.go)

✅ 线程安全: mutex 保护 bars 和 liveSigs。
✅ 启动/停止: Start/Stop 通过 channel 控制。

| 行 | 严重度 | 问题 |
