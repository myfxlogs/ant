# 地基审计框架

> 8 个地基模块：mql-compiler / strategy-runtime / backtest-engine / market-data / mt-gateway / risk-gate / api-gateway / account-mgmt
> 方法：三步——快速扫描 → 管线深追 → 输出差异清单

---

## 第一步：快速扫描（逐块过，只标色）

每个块用同一套 6 维框架，只判断红/黄/绿，不深入。

| 维度 | 检查问题 |
|------|---------|
| 架构 | 分层干净？边界有泄漏？接口定义清晰？ |
| 接口 | 上下游契约明确？有隐藏依赖（import 不该引的包）？ |
| 代码质量 | 重复代码？死代码？文件大小超红线？ |
| 韧性 | 容错？重连？超时？降级？熔断？ |
| 测试 | 单测覆盖率？集成测试？边界条件？ |
| 缺失 | 该有但没有的能力？ |

每块输出一张审计卡片（10 行）：

```
## 块名 — 审计卡

| 维度 | 评分 | 备注 |
|------|------|------|
| 架构 | 🟢🟡🔴 | 一句话 |
| 接口 | 🟢🟡🔴 | 一句话 |
| 代码质量 | 🟢🟡🔴 | 一句话 |
| 韧性 | 🟢🟡🔴 | 一句话 |
| 测试 | 🟢🟡🔴 | 一句话 |
| 缺失 | 🟢🟡🔴 | 一句话 |

红标项：
- 问题1 — 影响 — 建议
- 问题2 — 影响 — 建议
```

## 第二步：管线深追（沿红线追根因）

只追第一步标记为红/黄的块。不审块内部——追块之间的数据流。

三条管线：

```
行情管线:   mt-gateway → market-data → strategy-runtime
交易管线:   strategy-runtime → risk-gate → oms → mt-gateway
回测管线:   market-data → backtest-engine → mql-compiler
```

每条管线检查：

| 检查点 | 审计问题 |
|--------|---------|
| 数据转换 | 跨块边界时类型、精度、单位是否被错误转换？ |
| 错误传播 | 上游错误下游是否正确感知？还是被吞掉？ |
| 超时一致性 | 上下游的超时策略是否一致？上游 5s 等下游 30s = 白等？ |
| 重试幂等 | 重试是否引入副作用？下游是否做了幂等？ |
| 状态一致性 | 同一实体在上游和下游的状态是否同步？有不一致窗口吗？ |
