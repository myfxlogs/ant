# P4 Agent 循环管线逐行审计 — 2026-08-01

## 数据流

P4 有**两套独立的 Agent 循环实现**，分别走不同路径：

```
Path A (Chat Agent):  SSE → StrategizePlan/ExecutePlan
    → AgentLoop (no write_strategy tool)
    → LLM outputs code in text
    → ExtractCode → return to frontend

Path B (Generation Agent): gRPC → SubmitStrategy
    → AgentLoop (with write_strategy tool)
    → write_strategy: compile → fetchBars → VM backtest
    → profile → LLM analysis → blind-spot bridge
    → persist + return
```

## 逐环节审查

## 架构问题

### 两套 Agent 循环并存

| | Chat Agent | Generation Agent |
|---|---|---|
| 入口 | `connect/ai/strategy_plan_handler.go` | `agent/gateway.go` |
| 工具集 | read_kline, read_backtest_log, compile_python_chat | write_strategy, read_kline, edit_code, read_current_code, update_plan |
| write_strategy | ❌ 未注册 | ✅ 注册 |
| 回测 | ❌ 不执行 | ✅ 在工具内执行 |
| 代码提取 | ExtractCode (文本正则) | 工具参数 (结构化) |
| Prompt | 硬编码 "Python", "write_strategy" | 通过 tools 动态生成 |

两套实现共享 `AgentLoop` 核心但工具集不同，行为不一致。Chat Agent 路径的 prompt 引用 Generation Agent 的工具——架构债务。

**总评**: P4 管线的 I1/I2/I4 三个关键不变量（代码只能通过工具提交、工具内编译+回测、透明输入）在 Generation Agent 路径中正确实现。Chat Agent 路径存在 prompt-工具不一致的架构缺陷——模型被告知使用一个不存在的工具。两套并行实现是已知架构债务（审计 A-006 agent-engine 分层倒置的延伸）。
