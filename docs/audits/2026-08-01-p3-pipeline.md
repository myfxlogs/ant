# P3 订单对账管线逐行审计 — 2026-08-01

## 数据流

```
MT5 broker (gRPC stream)
    │ OnOrderUpdate RPC
    ▼
parseMt5OrderUpdate → mdtick.OrderUpdate
    │ decimal.NewFromFloat (API边界，合规)
    ▼
deps.OnOrderUpdate(accountID, userID, update)
    │
    ├── publishPositionSnapshot → PositionSnapshotBroker → SSE → 前端实时持仓
    │
    └── writeClosedTradeRecord → PG trade_records 表
            │
            ▼
    订单对账 (reconciliation.go) — 事件驱动，非轮询
```

## 逐环节审查

### 1. MT5 订单流接收 (adapter/mt5/order_stream.go)

✅ 指数退避重连: 1s → 2s → 4s → ... → 5min max。
✅ 流错误处理: `handleStreamError` 在非取消错误时断开 + 熔断。
✅ decimal←float64 边界: `decimal.NewFromFloat` 用于所有金额字段——正确的外部 API 边界。
✅ 重连时正确 Cancel 旧订阅: `cancelOrderUpdateSub` 在 `g.mu.Lock()` 下替换。

| 行 | 严重度 | 问题 |
|----|--------|------|
| 67-80 | 🟡 MEDIUM | 接收循环无 `defer recover`——如果 `handler(parseMt5OrderUpdate(...))` panic，goroutine 崩溃，订单流静默停止。外部已有重连循环但 panic 不可恢复 |
| 122-132 | 🔵 LOW | `decimal.NewFromFloat` 用于所有金额——协议边界正确，但 MT5 proto 的 float64 精度损失被继承（不是 mthub 的问题） |
| 155-160 | 🔵 LOW | `profitPct` 用 `InexactFloat64()` 截断到 float64——仅用于前端显示，不参与计算，可接受 |

### 2. 订单回调处理 (cmd/server/pipeline_callbacks.go)

✅ 持仓快照发布正确: 全量 PositionSnapshot → broker.Publish → SSE 推前端。
✅ 已平仓记录写入: 仅 close 事件 + CloseTime > 0 时写入。

| 行 | 严重度 | 问题 |
|----|--------|------|
| 28 | 🟡 MEDIUM | `context.WithTimeout(context.Background(), 5s)` ——丢失 trace 传播。如果调用链需要追踪，链路在此断裂 |
| 55-61 | 🔵 LOW | `uuid.Parse(accountID)` 失败时静默 return——accountID 是 UUID 格式 (mt_accounts_v2.id)，但注释未说明格式假设 |
| 72 | 🟡 MEDIUM | PG 写入失败仅 Warn 日志——无重试、无 DLQ。PG 短暂故障时已平仓记录永久丢失 |

### 3. TradeBroker 发布 (mthub/trade_broker.go)

| 行 | 严重度 | 问题 |
|----|--------|------|
| 78-91 | 🔴 HIGH | **Send-on-closed-channel 竞态**: `Publish()` 在 `RUnlock` 后遍历 channel 并发送，但 `cancel()` 可在此时 close channel。与 tick_broker.go 完全相同的模式——**进程 panic 风险** |
| 62-73 | 🟡 MEDIUM | `cancel()` 在 Lock 下 close channel——正确的关闭时序，但与 Publish 的 RUnlock→send 形成竞态 |

### 4. 交易事件存储 (mthub/trade_event_store.go)

✅ NATS JetStream 发布: `Nats-Msg-Id` header 保证至少一次投递 + 幂等去重。
✅ Proto UTF-8 重试: 首次 marshal 失败时 sanitize 3 个字段后重试——处理 MT4 非 UTF-8 数据。
✅ Trace 注入: `interceptor.InjectNATSTraceHeaders` 传播追踪信息。

| 行 | 严重度 | 问题 |
|----|--------|------|
| 103-113 | 🔵 LOW | Proto sanitize 仅处理 3 个字段 (Canonical, Broker, ClientID)——Side, OrderType 等其他 string 字段也可能包含非法 UTF-8（概率极低） |
| 128 | 🔵 LOW | NATS publish 错误直接返回——调用方 (oms_writer.go Transition) 忽略此错误 (`_ = w.store.Publish`)，事件可能丢失但 OMS 状态已更新。设计权衡：状态一致性 > 事件完整性 |
